Git 仓库历史截断与特定快照保留指南

2026.02.24 Linux

1. 彻底重置 main 和 classic（只留当前快照）

我们不再用 filter-repo 过滤，直接原地“毁档重开”：

# 重置 main
dotfiles checkout main
dotfiles checkout --orphan temp_main
dotfiles add -A
dotfiles commit -m "Final main snapshot"
dotfiles branch -D main
dotfiles branch -m main

# 重置 classic
dotfiles checkout classic
dotfiles checkout --orphan temp_classic
dotfiles add -A
dotfiles commit -m "Final classic snapshot"
dotfiles branch -D classic
dotfiles branch -m classic

2. 彻底重置 v0.8 和 v0.9（只留当时快照）

这是解决你“还能 checkout 到旧记录”的关键。我们必须把 Tag 重新打在“孤立点”上。

# 让 v0.8 变成一个没有父节点的独立提交
dotfiles checkout v0.8
dotfiles checkout --orphan temp_v08
dotfiles add -A
dotfiles commit -m "Final v0.8 snapshot"
dotfiles tag -f v0.8  # 把 v0.8 标签强行移动到这个新点上
dotfiles checkout main
dotfiles branch -D temp_v08

# 让 v0.9 同样操作
dotfiles checkout v0.9
dotfiles checkout --orphan temp_v09
dotfiles add -A
dotfiles commit -m "Final v0.9 snapshot"
dotfiles tag -f v0.9
dotfiles checkout main
dotfiles branch -D temp_v09

3. 物理粉碎（解决“为什么还能找到旧哈希”）

执行完上面的步骤，旧的历史在“名义上”已经删了。现在我们要从“硬盘上”抹掉它们：

# 1. 销毁所有操作记录（这是旧提交最后的藏身处）
rm -rf .dotfiles/logs/

# 2. 强制执行垃圾回收，清理所有无主对象
dotfiles gc --prune=now --aggressive

验证清理结果

执行完上面的 gc 命令后，请做两个测试：

  1. 查总数：运行 dotfiles rev-list --all --count。如果结果是 4，说明你的目标达成了！全仓库只有 4 个提交。

  2. 如果计数不是 4，我们需要把所有“拉住”旧历史的绳子全部剪断。请按照以下步骤执行：

1. 找出是谁在“拖后腿”

运行以下命令，看看除了你想要的 4 个东西，还有哪些引用存在：

dotfiles show-ref

你会发现输出里可能包含：

  • refs/remotes/origin/...（远程仓库的镜像副本）
  • refs/original/...（dotfiles-filter-repo 留下的备份）
  • refs/pull/...（dotfilesHub 的拉取请求记录）

2. 彻底大扫除（清理所有非必要引用）

请依次执行以下命令，这会强行删掉除了本地分支和标签以外的所有记录：

# 1. 删除所有远程追踪分支（它们是旧历史的最大藏身处）
dotfiles remote remove origin

# 2. 删除 dotfiles-filter-repo 产生的备份引用
dotfiles for-each-ref --format="%(refname)" refs/original/ | xargs -n 1 dotfiles update-ref -d

# 3. 再次强制清理 Reflog 和运行 GC
rm -rf .dotfiles/logs/
dotfiles reflog expire --expire=now --all
dotfiles gc --prune=now --aggressive

3. 再次检查计数

现在再运行：

dotfiles rev-list --all --count

如果现在的数字变成了 4（或者接近 4 的个位数）： 说明清理成功了！

提交到远程

1. 重新关联远程仓库

如果你在清理过程中运行了 dotfiles remote remove origin，需要先把它加回来：

dotfiles remote add origin <你的远程仓库URL>

2. 检查远程追踪分支（关键）

在推送前，确保本地没有 origin/main 之类的引用还在拉扯旧历史。你可以运行：

dotfiles branch -r

如果还看到很多远程分支，建议先清理它们，防止旧数据被意外带回。

3. 强制推送所有内容

你需要一次性将这 4 个“孤岛”（两个分支，两个标签）强行覆盖到服务器：

# 1. 强制推送所有分支 (main 和 classic)
dotfiles push origin --force --all

# 2. 强制推送所有标签 (v0.8 和 v0.9)
dotfiles push origin --force --tags

对于其他机器上的老仓库，由于你已经在远程彻底重写了历史，老仓库的 dotfiles 逻辑会判定这属于**“历史完全无关”**（Unrelated histories），传统的 dotfiles pull 会直接报错。

这些老机器必须执行“毁档重连”的操作。这里有两种方案，推荐第一种：

方案一：最简单彻底（推荐）

如果老机器上没有未提交的代码，直接删掉文件夹重新 Clone 是最省心的。

rm -rf <旧仓库目录>
dotfiles clone <仓库地址>

方案二：保留本地并同步（原地更新）

如果你不想重新克隆，必须强行让本地的 main 和 classic 指向远程的新“孤岛”。

请在老机器的仓库目录下执行以下命令：

1. 抓取远程新结构

# 强制抓取所有远程更新，忽略历史差异
dotfiles fetch --all --prune

2. 强行重置本地分支

不要用 pull，要用 reset 把本地分支直接“钉”在远程的最新提交上：

# 重置本地 main
dotfiles checkout main
dotfiles reset --hard origin/main

# 重置本地 classic
dotfiles checkout -B classic origin/classic

3. 更新标签 (Tags)

因为 v0.8 和 v0.9 的内容变了但名字没变，本地 dotfiles 默认不会更新已存在的标签。你需要强行覆盖：

dotfiles fetch --tags --force

4. 彻底物理清理老历史

为了让老机器的硬盘也释放那 600 多个提交的空间，最后执行清理：

dotfiles reflog expire --expire=now --all
dotfiles gc --prune=now --aggressive

⚠️ 注意事项

  • 未提交的代码：如果老机器上有还没上传的代码，在执行 dotfiles reset --hard 前，请务必手动备份。因为这个操作会抹除所有未提交的修改。
  • 孤魂野鬼：如果不执行 dotfiles gc，老机器虽然 log 变干净了，但 .dotfiles 文件夹体积依然是旧的大小。
