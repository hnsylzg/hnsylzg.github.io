用 git-filter-repo 清除仓库中的文件

2026.02.24 Linux

Git 官方现在推荐使用 yay -S git-filter-repo

  • 删除文件：安装后，运行：
dotfiles filter-repo --path path/to/big-file.zip --invert-paths
不行就加上
dotfiles filter-repo --path path/to/big-file.zip --invert-paths --force

这会遍历整个提交历史，把涉及该文件的记录全部抹除。

在清理完成后，你需要重新添加远程地址：

# https
dotfiles remote add origin https://github.com/username/dotfiles.git
# ssh
dotfiles remote add origin git@github.com:username/dotfiles.git
# 修改
dotfiles remote set-url origin git@github.com:username/dotfiles.git
强制推送
dotfiles push --force --all

其他机器同步

同步所有分支

# 获取远程更新
dotfiles fetch origin
# 查看分支，只看到 * main，说明你的 Bare 仓库配置文件（config）里的 fetch 规则可能丢失了。
dotfiles branch -a
# 查看远程抓取配置
dotfiles config --get remote.origin.fetch
# 如果返回为空
dotfiles config remote.origin.fetch "+refs/heads/*:refs/remotes/origin/*"
# 然后再次抓取
dotfiles fetch origin
# 方法1
dotfiles reset --hard origin/main
dotfiles branch --set-upstream-to=origin/main main
# 方法2
dotfiles fetch origin main
dotfiles reset --hard FETCH_HEAD
dotfiles branch --set-upstream-to=origin/main main

分支

# 1. 强制抓取远程 classic 分支的最新状态
dotfiles fetch origin classic
# 2. 强行将本地当前分支重置为远程的 classic
dotfiles reset --hard FETCH_HEAD
# 3. 建立（或恢复）追踪关系
dotfiles branch --set-upstream-to=origin/classic classic

清理本地库

# 清除所有旧的引用日志
dotfiles reflog expire --expire=now --all
# 彻底清理并重新打包数据库（这步最耗时，但最有效）
dotfiles gc --prune=now --aggressive
